# UART-Based Digital System — Verilog RTL Project

Complete dual-clock-domain UART command/ALU/RegFile system, implemented
per the attached "Final System" specification. Every block has its own
RTL file and its own testbench; two domain-level top modules integrate
the sub-blocks, and `sys_top` / `tb_sys_top` integrate the whole chip.

All RTL is synthesizable Verilog-2001 style (compiled/simulated here
with Icarus Verilog `-g2012`, but no SystemVerilog constructs are
required). Every testbench is self-checking (prints `PASS`/`FAIL` per
check and a final `*** TB_<NAME>: ALL TESTS PASSED ***` banner) and
was actually compiled and simulated with `iverilog`/`vvp` — see
`run_all_tests.sh`.

## Directory layout

```
rtl/
  rst_sync.v       clkdom1_top.v     uart_top.v
  regfile.v        clk_div.v         data_sync.v
  alu.v            uart_tx.v         sys_top.v
  clk_gate.v       uart_rx.v
  sys_ctrl.v       pulse_gen.v
  async_fifo.v
tb/

sim/                iverilog .vvp / .vcd outputs (generated by run_all_tests.sh)

```

## Block → file map (matches the spec's 10-block breakdown)

| Spec block            | File               | Notes |
|------------------------|--------------------|-------|
| RegFile                 | `rtl/regfile.v`    | 32×8 (see assumption #1) |
| ALU                      | `rtl/alu.v`        | 14 ops, see encoding below |
| Clock Gating             | `rtl/clk_gate.v`   | latch-based, glitch-free |
| SYS_CTRL                 | `rtl/sys_ctrl.v`   | command FSM |
| UART_TX                  | `rtl/uart_tx.v`    | 1 bit / CLK edge |
| UART_RX                  | `rtl/uart_rx.v`    | 16x oversampled |
| PULSE_GEN                | `rtl/pulse_gen.v`  | Busy falling-edge → pulse |
| Clock Dividers (x2)      | `rtl/clk_div.v`    | instantiated twice in `uart_top.v` |
| RST Synchronizer (x2)    | `rtl/rst_sync.v`   | instantiated twice in `sys_top.v` |
| Data Synchronizer (x3)   | `rtl/data_sync.v`  | instantiated 3x in `sys_top.v` |
| ASYNC FIFO               | `rtl/async_fifo.v` | gray-code, inside `uart_top.v` |

Integration:
- `clkdom1_top.v` — Clock Domain 1 (REF_CLK): RegFile + ALU + Clock
  Gating + SYS_CTRL.
- `uart_top.v` — Clock Domain 2 (UART_CLK): UART_RX, UART_TX,
  PULSE_GEN, ASYNC_FIFO, and the two CLKDiv instances (TX baud divider
  and RX oversample divider).
- `sys_top.v` — final system: 2× RST synchronizers, `clkdom1_top`,
  `uart_top`, and 3× Data_Sync bridges (UART config REF_CLK→UART_CLK
  ×2, received-byte UART_CLK→REF_CLK ×1).

## How to run

```
./run_all_tests.sh
```
This compiles and simulates all 14 testbenches with Icarus Verilog and
prints a pass/fail summary line per block, ending in one final banner.
Each run also drops a `.vcd` waveform under `sim/` for inspection in
GTKWave if you want to look at any block in more detail.

## Design assumptions (the spec document left these details implicit)

The source spec is a block/interface diagram plus a protocol summary;
a few concrete choices had to be made to turn it into working RTL.
These are called out here rather than buried in code comments alone:

1. **RegFile address width.** The interface table lists the address
   bus as "4 bits (default)", but the documented normal-operation
   address range is `0x4`–`0x15`, which needs 5 bits. `regfile.v` uses
   `ADDR_WIDTH = 5` (32 locations) to actually satisfy the spec's own
   addressing requirement.

2. **Command frame order.** The frame tables in the doc list columns
   as "Frame 2 / Frame 1 / Frame 0" with the command byte in the
   highest-numbered column, which would put the opcode LAST on the
   wire — but a receiver can't know how to parse frames it hasn't
   identified the command for yet. `sys_ctrl.v` assumes the
   **command/opcode byte is always sent first**, followed by its
   operands, e.g. `RF_WR = {0xAA, ADDR, DATA}` (3 frames total),
   `ALU_OP = {0xCC, OPERAND_A, OPERAND_B, ALU_FUN}` (4 frames).

3. **ALU_OUT width.** The ALU's own interface table specifies an
   8-bit `ALU_OUT`, while SYS_CTRL's table lists a 16-bit input of the
   same name. `alu.v` keeps `ALU_OUT` at 8 bits (matching the rest of
   the 8-bit datapath and the RegFile/UART word size); multiplication
   returns only the low byte. If a 16-bit result path is actually
   wanted, `alu.v`'s `MUL` case is the only place that needs widening.

4. **Prescale vs. Div_Ratio relationship.** The block diagram shows
   two independent `ClkDiv` instances — one for UART_TX driven by
   `Div_Ratio` (REG3), one for UART_RX driven by `Prescale`
   (REG2[7:2]) — with no formula tying them together. `uart_rx.v`
   fixes its internal oversampling at `OVERSAMPLE = 16` ticks/bit, so
   for the TX and RX sides to run at the *same* effective baud rate:

   ```
   Prescale = Div_Ratio / 16
   ```

   The register file's power-on defaults (`Prescale = 32`,
   `Div_Ratio = 32`) do **not** satisfy this and will make TX and RX
   run at very different bit rates (a 16× mismatch) if left
   unconfigured. `tb_sys_top.v`'s master reprograms both registers
   early on (`Div_Ratio = 16`, `Prescale = 2`) precisely to get a
   matched, simulation-friendly baud rate — mirroring the spec's own
   required "configuration first" sequence.

5. **`ASYNC_FIFO.R_CLK` connection.** The signal table lists
   `R_CLK`'s "Connected to" as `RST_SYNC_2`, which is a reset
   synchronizer, not a clock source — clearly a documentation
   copy/paste artifact. `uart_top.v` connects `R_CLK` to `UART_CLK`
   itself (the undivided domain-2 clock) and `R_RST` to
   `RST_SYNC_2`'s output, which is the only combination that makes
   sense functionally.

6. **TX kick-start / FIFO draining glue.** `PULSE_GEN` only produces a
   pulse on UART_TX's `Busy` falling edge, so it can't start the very
   first transmission after an idle period (no prior Busy transition
   to key off). `uart_top.v` adds a small edge-triggered "kick"
   (fires once when the FIFO transitions empty→non-empty while TX is
   idle) to start the first byte, alongside the Busy-falling-edge
   pulse for subsequent bytes. Both are carefully built only from
   *registered* copies of the FIFO's `EMPTY` flag — using the live,
   combinational `EMPTY` output directly in this glue logic recreates
   a zero-delay feedback loop (`EMPTY` is computed look-ahead from
   `R_INC`, and `R_INC` was, in an earlier draft, computed from live
   `EMPTY`) that shows up as `X` propagation in simulation.

## Hard-won CDC/timing bugs found via simulation (kept as comments in the RTL)

Building this bottom-up in Icarus Verilog surfaced several real bugs
that are easy to miss by inspection alone:

- **`async_fifo`**: gating the pointer *increment* on `FULL`/`EMPTY`
  (as some textbook versions do) creates a combinational loop, since
  `FULL`/`EMPTY` are themselves derived from the pointers. Fixed by
  incrementing pointers unconditionally on `W_INC`/`R_INC` and trusting
  the caller not to assert them while full/empty (standard for this
  FIFO style). A related, subtler version of the same bug then showed
  up when `RD_DATA`'s update was still gated by `!EMPTY` — since
  `EMPTY` is a look-ahead (next-state) signal that already reflects
  the *pending* read, that gate silently dropped the last word of a
  burst.
- **`uart_top` TX glue**: the "kick-start" and "drain-next-byte" logic
  went through three iterations before landing on the fully-registered
  edge-detector described in assumption #6 above — every earlier
  version either created a same-cycle combinational loop through the
  FIFO's `EMPTY` flag, or spuriously re-popped the FIFO while a byte
  was already latched and waiting for `UART_TX` to accept it,
  eventually desynchronizing the FIFO's read pointer past its write
  pointer (an internal underflow with no self-correction).
- **`data_sync` reset value**: crossing REG2/REG3 (UART config) from
  REF_CLK into UART_CLK using a `data_sync` that resets its output to
  0 created a boot-time race — the very first "sync the power-on
  default" pulse could be (and, in simulation, was) missed if the
  destination domain's reset synchronizer took longer to deassert than
  the source pulse's stretch window. Fixed with a `RESET_VAL`
  parameter so the synchronized config bus starts at the *correct*
  power-on value directly, independent of that race.
- **`uart_rx` parity/stop flags**: `PAR_ERR` was originally raised one
  bit-period *before* `DATA_VLD`, so a consumer sampling on `DATA_VLD`
  never saw it. Fixed by latching the parity check result and only
  presenting `PAR_ERR` alongside `DATA_VLD`/`STP_ERR` once the full
  frame (including the stop bit) has been received.

## ALU opcode encoding (`ALU_FUN[3:0]`)

| Code | Op | Code | Op |
|------|----|------|----|
| 0000 | ADD | 1000 | XOR |
| 0001 | SUB | 1001 | XNOR |
| 0010 | MUL (low byte) | 1010 | CMP A==B |
| 0011 | DIV (÷0 → 0) | 1011 | CMP A>B |
| 0100 | AND | 1100 | SHR (A>>1) |
| 0101 | OR | 1101 | SHL (A<<1) |
| 0110 | NAND | | |
| 0111 | NOR | | |

## Command protocol (as implemented in `sys_ctrl.v`)

| Command | Opcode | Frames (in order) | Reply |
|---------|--------|--------------------|-------|
| RF Write | `0xAA` | CMD, ADDR, DATA | none |
| RF Read  | `0xBB` | CMD, ADDR | 1 byte: RdData |
| ALU op (with operands) | `0xCC` | CMD, OPERAND_A, OPERAND_B, ALU_FUN | 1 byte: ALU_OUT |
| ALU op (no operand, reuse REG0/REG1) | `0xDD` | CMD, ALU_FUN | 1 byte: ALU_OUT |

Every UART frame is 1 start bit + 8 data bits (LSB first) + optional
parity (per REG2) + 1 stop bit.
